# Автодиспетчер — первый прототип

Веб-приложение для демонстрации грузовой работы станции и приоритизации подходящих вагонов. Node.js 22+, без внешних библиотек для запуска; интерфейс на русском языке.

## Запуск

```sh
npm start
```

Открыть http://127.0.0.1:3000. Порт меняется через `PORT=3001 npm start`. По умолчанию сервер слушает только loopback. `npm run dev` перезапускает сервер при изменениях файлов. Перезапуск сбрасывает состояние.

## Что работает

- Выбор любой из шести станций непосредственно в SVG-поездограмме или на схеме участка.
- Десять подъездных путей на станции D: специализация, вместимость, грузовой фронт, производительность, занятость, обработанные вагоны, резерв, доступная ёмкость, предполагаемое освобождение.
- Раздельные операции завершения обработки и уборки. Обработанные вагоны занимают путь до уборки.
- Подход грузовых групп: исходное местоположение, условное расстояние, ETA, срок доставки, прогнозный запас срока, возможность приёма.
- Резервирование целой группы на подходящем пути, отмена резерва, приём после ETA. Резерв нельзя занять другой группой. Грузовой фронт ограничивает число вагонов под операциями; остальные ожидают.
- Продвижение модельного времени на 15/60 минут, завершение операций по времени, журнал событий.
- Учебное закрытие нечётного пути D–E, заранее заданное предложение, подтверждение диспетчера и восстановление исходной схемы.
- SSE: изменения состояния сразу видны во всех открытых вкладках. Heartbeat раз в секунду; время симуляции продвигается вручную.
- Поиск, фильтры, CSV-отчёт, адаптивный интерфейс.

## Сценарий показа

1. Откройте станцию D (Казан), выбранную по умолчанию. На пути 1 находится 10 вагонов: 8 обработаны, 2 под операциями.
2. Нажмите «Завершить». Обработанных станет 10, но доступная ёмкость пути останется нулевой.
3. Нажмите «Убрать 10». Теперь на путь можно подать 10 вагонов.
4. Перейдите в «Подход вагонов». Срочная группа с нефтепродуктами не помещается на подходящий путь. Группу зерна из Майтак можно запланировать раньше группы из Караганды, у которой запас срока больше.
5. Зарезервируйте группу: число доступных мест уменьшится, физическая занятость пока останется прежней. Повторный резерв невозможен.
6. Продвиньте время пять раз на один час. Примите группу из Майтак. Вагоны попадут на грузовой фронт либо в ожидание фронта.
7. Включите закрытие D–E, рассмотрите учебный вариант и подтвердите его. Выгрузите CSV и проверьте журнал.

## Модель

Занятость = вагоны под операциями + обработанные + ожидающие фронта.

Доступная ёмкость = вместимость − занятость − подтверждённые резервы.

Путь должен соответствовать грузу и вмещать всю группу. Распределения одной группы по нескольким путям в первой версии нет. Общая доступная ёмкость станции не означает возможность приёма любого груза.

Порядок рекомендаций: меньший запас срока после `max(текущее время, ETA) + длительность обработки группы + 30 минут на уборку`. Длительность обработки группы — число партий по размеру фронта, умноженное на сумму длительности операции пути и 30 минут на уборку каждой партии. Среди подходящих путей выбирается путь с меньшей общей длительностью обработки группы. Это прозрачная эвристика, а не сетевой оптимизатор. Прогноз не моделирует очередь маневрового локомотива и других ресурсов. Если нет пути нужной специализации, запас срока не рассчитывается.

Ожидаемое освобождение — окончание текущей операции плюс 30 минут на плановую уборку и время обработки/уборки ожидающих партий; оно не освобождает ёмкость автоматически. В демо окончательную уборку подтверждает пользователь.

## Архитектура

```text
Браузер (HTML / CSS / JS / SVG)
       │ POST /api/action
       ▼
Node.js HTTP → модель станции и эвристика приёма
       │ состояние в памяти, журнал до 100 событий
       └── GET /api/events (SSE) → все браузеры
```

- `server/model.js` — синтетические данные, модель ёмкости, рекомендации, действия и проверки.
- `server/index.js` — HTTP, JSON API, SSE, статические файлы.
- `public/` — интерфейс, график, схема, отчёт.
- `test/model.test.js` — проверки бизнес-правил и последовательностей операций.

## API

- `GET /api/state`: текущее состояние с вычисленными полями.
- `GET /api/events`: SSE со снимком при подключении и после каждого действия.
- `POST /api/action`: JSON. Действия: `complete/clear` + `trackId`; `reserve/cancel/arrive` + `groupId`; `advance` + `minutes` (15, 30, 60); `block`, `approve`, `reset`.
- Некорректные действия возвращают HTTP 400 с полем `error`.

```sh
curl -X POST http://127.0.0.1:3000/api/action \
  -H 'Content-Type: application/json' \
  -d '{"type":"complete","trackId":"D-1"}'
```

```sh
npm run check
npm test
```

Браузерные проверки (Chromium):

```sh
npm ci
npx playwright install chromium
npm run test:e2e
```

Проверяют грузовые операции, резерв и отмену, выбор станций, поиск, фильтры, сценарий закрытия, синхронизацию двух вкладок, CSV, ошибки API и мобильную ширину. Тестовый сервер использует отдельный порт 3174. Снимки интерфейса сохраняются в `test-results/`.

## Границы первой версии

Все данные синтетические. Имена станций — визуальные ориентиры; схема А–F, расстояния и сроки не описывают реальную топологию сети. Часы привязаны к 1 октября 2026 года, часовому поясу Asia/Almaty. Позиции на сети не обновляются: показываются исходная станция и исходное оставшееся расстояние.

Поездограмма иллюстративная; закрытие D–E добавляет фиксированные 40 минут к ETA грузовых групп. Это заранее заданный демонстрационный сценарий. Нет расчёта бесконфликтного плана, независимого валидатора безопасности, автоведения, управления сигналами, реальных интеграций, уведомлений пассажирам и индекса качества движения. Демонстрация не заменяет СЦБ и другие сертифицированные системы безопасности.

Нет авторизации, БД, восстановления истории после перезапуска, перемотки истории и PDF. Состояние смены общее для всех вкладок локального сервера. CSV содержит отчёт по выбранной станции и общий журнал событий.

Дальнейшее развитие: сохраняемое хранилище и авторизация; планирование маневровых ресурсов и будущих окон приёма; импорт сетевого подхода; настоящий планировщик движения с независимым валидатором; история состояний и автоведение.
